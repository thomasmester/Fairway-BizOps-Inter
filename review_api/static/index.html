How the Review Desk works

    
One Flask service on Render sits between the people and Claude. Clerks' comments come in, Claude turns each one into a structured verdict, and the form editor gets a queue sorted by priority. Nothing on the board is precomputed: every ticket is a live Claude call.

  


  

    
  


  

    

      
What happens to one comment

      
    
        
  1. Capture. The page sends POST /api/feedback with the comment, customer, state, form and field. The API checks lengths and, when set, the access key.
    2. 
        
  2. Context. The API loads the open tickets for the same customer and form, so Claude can spot a comment that contradicts an earlier one.
    3. 
        
  3. Classify. triage.py sends the comment and that context to Claude Opus 5 with a fixed JSON schema. Claude returns intent, category, priority, route, fix and what to verify.
    4. 
        
  4. Store. The ticket is saved in SQLite. If Claude flagged a conflict, both tickets are linked. Ticket IDs Claude didn't receive are discarded.
    5. 
        
  5. Notify. Every ticket posts to the editor feed. High and critical tickets also go to the webhook when one is configured.
    6. 
        
  6. Work the queue. The board polls /api/queue and the editor acknowledges or resolves tickets with PATCH /api/tickets/<id>.
    7. 
      

    

    

      
What Claude returns

      

        
FieldValues

        
categorymapping error, fill rule error, customer preference, extraction error, form version, conflicting, unclear, not an error

        
prioritycritical, high, medium, low

        
route_toform editor, extraction team, forms team, account owner

        
scopeall customers, this customer only, verify first

        
error_summary, suggested_fix, verification_stepPlain-language text for the editor

        
conflicts_withIDs of open tickets this comment contradicts

        
intent, confidenceWhat the customer wants; high, medium or low

      

    

    

      
Priority rules given to Claude

      

        
PriorityMeaning

        
CriticalEvery filing on the form is at risk, e.g. an outdated form version

        
HighA legally significant field is wrong: party names, VIN, lienholder, odometer, price

        
MediumA decision is needed first: preferences, conflicts, unconfirmed state rules

        
LowCosmetic issues and questions
