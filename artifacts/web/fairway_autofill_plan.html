Fairway Business Operations case · Autofill launch

Calibrate Autofill where our customers already file

Autofill has zero mapped forms and one calibrator doing one form a day. The first month should buy traction: live customers filing real paperwork through Autofill. So the order follows existing-customer usage, led by our biggest account, then the promises we've already made. Pipeline dollars and market size only break ties.

The plan · one form per day

Main forms first, then the rest

Each state is assumed to need two forms: a new-vehicle title and a used or transfer title. Wave 1 calibrates the busier form in each state (Texas gets both). Wave 2 finishes the rest by volume.

Dark = wave 1, light = wave 2. The coverage figure is the share of the 200 recent transactions that can run through Autofill by the end of that day.

Pipeline adjustments

  • D10, $2.5M: excluded. It's Audit only, so it needs no Autofill forms.
  • D08, $2.0M: 50% haircut. It depends on a state fee bill passing.
  • D06, $1.2M: 25% haircut. The close date has passed, and it's been stuck in legal since May.
  • D05, $900K: 50% haircut. It's at Discovery, and the amount is the rep's guess.
  • D19: lost because we had no Autofill. That's a demand signal for NY, NJ and PA.

How much to trust it

  • Moving each weight ±10 points (11 scenarios): 8 states stay in the top 10 every time. CA is in 10 of 11, VA in 9, and Arkansas swaps in 3 times.
  • Only 5 days of transactions, including a weekend.
  • One customer is 68% of the sample. That's intended, but it's also concentration risk.
  • The number of forms per state is assumed, not known.
Part 2 · Customer feedback

Nothing changes until it's verified and scoped

Feedback is a signal, not an instruction. Some comments are mapping errors, some are extraction bugs, some are one clerk's preference, and some contradict each other.

  1. CaptureLog each comment against its form, field, transaction and customer
  2. ClassifyMapping, condition, preference, extraction, form version or conflict
  3. VerifyCheck the DMV rule and the source documents first
  4. ScopeGlobal state rule, or a per-customer override
  5. ChangeEdit the mapping record, with the reason and a link to the comment
  6. TestRegression-test on past transactions for that form
  7. Close the loopReply to the customer and track repeat errors per form

Before committing

What I'd want to know

  1. How many forms each state really needs, and whether mappings can be reused across states.
  2. Whether 5 days is representative. I'd want 3–6 months of history per customer and state.
  3. Which states customer 87 would move to Autofill first under the D01 expansion.
  4. Hard dates: the D09 Q4 deadline, the D03 POC scoring date, and when D07 needs Autofill live.
  5. Whether Audit's existing state rule sets can speed up calibration.
  6. Whether any DMV form changes are pending in the top 10 states.
